## 二、数据集特征说明

### 2.1 数据来源

本项目角色为网络梗角色“奶娃”（naiwa，黄色圆身、奶油色肚皮、大圆眼笑脸）。
公开数据集调研后未找到可用数据（HuggingFace 上的 NailongClassification 实为动漫人物图，已排除），
因此走**自建数据集**路线：

- 从 GitHub 生态抓取（32 个素材仓库：spritesheet、GIF、表情包、游戏素材、图标），
  去重后共 **939 张**原始图（tools/collect_naiwa.py，2.8 分钟）；
- 自动过滤：黄色像素占比 > 4%、边框白底占比 > 60%、短边 ≥ 96px → 保留 **740 张**；
- 人工清洗：527 张去重图生成交互式 HTML 图库逐张勾选，删除 199 张
  （非奶娃主体、多主体、精灵表长图、图标/海报）→ **最终 328 张**精选素材。

### 2.2 数据集规模与组织

两条产品线使用同一批精选素材，但组织方式不同：

| 数据集 | 规模 | 形式 | 用途 |
| --- | --- | --- | --- |
| pix2pix 配对集 | 训练 **2358 对** / 测试 **65 对** | 每对为 `[HED 边缘图 \| 奶娃图]` 的 512×256 拼接 JPG | 训练 256px pix2pix 生成器 |
| LoRA v3 集 | **328 张** | 512×512 PNG，主体缩至 80% 居中贴白底 + 文本描述 | 微调 Stable Diffusion 1.5 的 LoRA |

- pix2pix 训练集由 262 张源图经 **9 倍手绘风格增强**（随机旋转、弹性形变、
  线宽抖动、断线模拟）扩充而成，测试集 65 张不参与训练；
- LoRA 描述示例：
  `naiwa, a cute yellow round creature with a cream belly, big round eyes and a smiling mouth, on white background`。

### 2.3 数据类型

- 图像数据：PNG/JPG，RGB，单主体、白底；角色姿态多样（正面/侧面/挥手/跳跃等）；
- 边缘图：由 HED 边缘检测器（ControlNetHED，学习式全嵌套边缘检测）从原图提取，
  白线黑底、无五官细节（眼睛/嘴的线条在阈值后处理中被过滤，此为后续“隐式加脸”问题的根源）；
- 测试输入（非训练数据）：画板手绘草图、真实照片（AFHQ 猫数据集子集、自拍）、
  视频文件、手机摄像头实时视频流。

### 2.4 数据特点与难点

1. 单一角色、跨图风格需一致 —— 生成模型要“认识角色”而不是泛化画卡通；
2. 素材清洁度参差 —— 混入过精灵表（网格排布多主体），曾导致模型高权重时输出整张网格；
3. 无配对标注 —— 边缘图全部由 HED 自动生成，属于弱监督建库。

## 三、测试应用说明（模型与算法）

> 课程要求以 SVM 为例说明测试应用的意义及相关内容。本项目测试应用为两类
> 图像生成模型，下面分别说明其“是什么、为什么用、关键内容”。

### 3.1 产品线 A：pix2pix 条件生成对抗网络（256px 极速版）

**意义与定位**：pix2pix 是“图像到图像翻译”的代表模型，适合有配对数据的场景。
我们用 2358 对（边缘图 → 奶娃图）训练它学习一对一的映射：输入一张线稿，
输出唯一的奶娃图。因推理只需一次前向传播，速度极快（≈14 ms/帧），
适合视频与实时直播场景。

**相关内容**：
- 生成器：U-Net 结构（编码-解码 + 跳跃连接），跳跃连接把输入轮廓的
  空间信息直达输出，保证“线稿什么形状，奶娃就什么形状”；
- 判别器：PatchGAN（对图像分块判断真假），关注局部纹理质量；
- 损失函数：条件对抗损失 + L1 重建损失（权重 λ=100），L1 保证输出与真值接近，
  对抗损失提升锐度；
- 训练配置：从零训练 240 epoch，batch size 8，lr 2e-4 线性衰减，
  训练集 2358 对，单 epoch ≈ 55 s。

### 3.2 产品线 B：SD1.5 + 自训 LoRA + ControlNet + LCM（512px 精细版）

**意义与定位**：通用扩散大模型（Stable Diffusion 1.5）不认识小众梗角色，
我们通过 LoRA 微调让模型“学会”画奶娃，再用 ControlNet 输入线稿约束形状，
用 LCM 蒸馏采样把生成步数压到 4~10 步，兼顾质量与速度。

**相关内容**：
- 扩散模型：前向过程对图像逐步加噪声，反向过程从纯噪声逐步去噪生成图像；
  训练目标是让网络学会预测每一步加入的噪声；
- 潜空间扩散：SD1.5 在 VAE 压缩的潜空间（64×64）上扩散，比像素空间快一个量级；
- 文本条件：CLIP 文本编码器把提示词编码为条件向量，`Classifier-Free Guidance (CFG)`
  放大文本条件的影响力；
- LoRA（Low-Rank Adaptation）：把权重更新分解为两个小矩阵的乘积 `ΔW = B·A`，
  只训练约 1% 的参数（rank=16），显存友好且不易灾难性遗忘，
  推理时可用强度系数缩放 LoRA 的影响；
- ControlNet：在扩散 UNet 旁并联一个可训练副本，以“零卷积”接入，
  接受线稿/边缘等结构条件，训练时原始 UNet 冻结，因此不破坏原有生成能力；
- LCM（Latent Consistency Models）与 LCM-LoRA：把一致性蒸馏引入潜空间扩散，
  使模型可用 4 步左右完成采样；LCM-LoRA 是可叠加的蒸馏适配器，
  与角色 LoRA 并联加载（适配器权重 [1.4, 1.0]）。

### 3.3 两条产品线对比

| | 产品线 A：pix2pix | 产品线 B：LoRA + ControlNet |
| --- | --- | --- |
| 分辨率 | 256px | 512px |
| 速度 | ≈ 14 ms/张 | ≈ 1.2~2.7 s/张 |
| 适用 | 视频逐帧、实时直播 | 画板、单图精修 |
| 风格 | 简洁、忠于线稿 | 更细腻，可自动补脸、微调表情 |
| 训练成本 | 240 epoch，约 4 小时 | 800 步，约 40 分钟 |

## 四、工作动机（目的与意义）

**目的**：把“手绘/照片/视频/直播 → 奶娃”做成一套完整可用的角色创作工具，
让不会画画的人也能在几秒内产出梗角色二创内容。

**要解决的问题**：
1. 手工绘制二创门槛高、周期长；
2. 通用大模型不认识小众角色，直接生成会“画成别的东西”；
3. 实时性与生成质量通常难以兼得（要快就得牺牲分辨率/细节）。

**意义与价值**：
- 创作自动化：画一个轮廓（甚至一根线条）就能得到完整角色立绘；
- 交互低门槛：画板、上传照片、视频、手机直播四种输入覆盖不同玩法；
- 实时互动：直播模式可把摄像头画面里的一切实时变成奶娃，现场演示效果好；
- 消费级可行性验证：全流程在 8 GB 显存笔记本上完成训练与推理，
  证明低成本跑通“数据自建 → 微调 → 部署 → 实时”的完整闭环。

## 五、问题挑战

### 5.1 整体学习与数据层面

1. **无现成数据集**：公开渠道无该梗角色数据集，需自行从 GitHub 生态收集，
   提炼出“黄色占比 + 白底比例 + 分辨率”的自动过滤规则，再做人工清洗。
2. **数据质量事故**：第一版 LoRA 数据混入精灵表（sprite sheet）网格图，
   导致模型在高权重时把输出排成网格崩坏图 —— 教训是数据清洗远比堆训练步数重要；
   最终以 527→328 的人工筛选+去重解决。
3. **评估方法学**：GAN 的 loss 曲线没有直观参考价值，学会用
   “训练过程周期出图 + 测试集 L1 + 逐 checkpoint 生成对比网格”做定性+定量联合评估。

### 5.2 系统搭建层面

1. **依赖与环境坑**：diffusers 训练脚本的 `variant` 缺省问题、GPU 数据集需
   `metadata.jsonl`；HuggingFace 的 Xet 传输协议在特定网络下卡死 →
   禁用 Xet、改用国内镜像并自写断点续传下载器绕过。
2. **8 GB 显存限制**：pix2pix 训练 batch=8 逐轮约 55 s；LoRA 训练采用
   batch=1 + 梯度累积 8 + 梯度检查点 + fp16，峰值 3.3 GB 稳跑。
3. **实时直播工程**：手机摄像头必须走 HTTPS（自签证书）；WebSocket 推流需
   “latest-wins”帧丢弃策略防积压；把 GPU 结果写到磁盘供电脑端显示时，
   遇到文件被占用锁导致连接崩溃，通过重试写入 + 帧级异常隔离修复；
   最终用 TAESD 微型 VAE 替换原生 VAE 解码，进一步提速。
4. **多人并发**：课堂演示十几人同时使用，Gradio 开队列（单卡串行），
   先到先服务自动排队，保证不崩。

### 5.3 模型学习层面（最关键的三次迭代）

1. **脸部缺失**：诊断发现 HED 生成的训练边缘图几乎不含眼睛/嘴的笔画
   （原始响应微弱，被后处理阈值洗掉），模型只渲染“画出来的五官”，
   空白轮廓永远没有脸。解决：v3 训练时在文本描述中显式写明
   “big round eyes and a smiling mouth”，模型按训练先验在身体上部自动补脸，
   实现“不用画五官也有脸”的隐式加脸效果（效果见 `docs/images/exp2_face_matrix.png`、
   `v3_face.png`）。
2. **背景崩坏**：v2 训练图全部是主体填满画面的紧裁剪，模型学到
   “填满画布”的先验，图片版输出整幅奶娃皮肤纹理、无白底。解决：
   v3 数据把主体缩到 80% 居中贴白底留白重训；推理端再叠加
   “控制图缩小 70% 居中 + 生成结果按主体掩膜白底合成”双保险
   （效果见 `docs/images/v3_imagebg_fix.png`、`v3_comp_refine.png`）。
3. **过拟合/欠拟合平衡**：早期 checkpoint 欠拟合（50 张 150 步 → 扁平）、
   后期过拟合（800 步 → 纹理漂移、构图崩）。解决：按评估择优选
   checkpoint-200/800，并按 LoRA 权重扫描确定甜点区 w=1.0~1.4。
   另发现 pix2pix 部分 checkpoint 因 BatchNorm 统计量震荡产生棋盘格伪影，
   逐 epoch 评估后弃用。

## 六、测试效果（模型评价）

### 6.1 pix2pix（产品线 A）

- **定量**：自建测试集（65 对）逐 epoch 的 L1 损失：
  epoch 100~240 稳定在 **≈0.030**，最优 epoch 180 为 **0.0302**
  （第一版模型约 0.032）；早期 epoch 30/50/80/90 存在棋盘格伪影，已弃用。
- **定性**（见 `docs/images/pix2pix2_epoch_grid.png`、`pix2pix_epoch_compare.png`）：
  epoch ≥100 后轮廓还原准确、白底干净、角色特征稳定；240 epoch 输出接近真值。
- **速度**：单帧 14 ms（纯 GPU 管线直播可达 ~68 fps；含每帧抠图 ~15 fps）。

### 6.2 LoRA v3（产品线 B）

- **定性**（见 `docs/images/v3_decide.png`、`v3_txt2img.png`）：
  checkpoint-200 综合最优 —— 全身构图、纯白背景、自动带笑脸；
  600 步尾部偏过拟合、800 步出现纹理/颜色漂移。
- **强度扫描**（见 `docs/images/lora_eval_weights.png`）：
  w=1.0~1.4 为甜点区；w≥1.5 出现噪点纹理；直播模式固定 w=1.2~1.5 各预设。
- **图片版修复效果**（见 `docs/images/v3_image_final.png`）：
  靴子照片 → 靴形奶娃带笑脸、纯白底；猫照片 → 猫形奶娃。

### 6.3 综合

- 两条线互补：课堂演示中 pix2pix 用于“秒出”体验，LoRA 用于精细展示；
- 现场结论：模型已能稳定做到“任意简笔画输入 → 可辨识的奶娃形角色”，
  且对完全未见过的新形状（蘑菇、靴子、瓶盖等）保持形状跟随能力。

## 七、心得体会

> 【请按实际团队情况扩写以下段落，并替换姓名/分工占位符】

1. **数据 > 模型**。三次最大的效果提升（去网格、补脸、修背景）全部来自
   数据与提示词的修改，而非换更大的模型或加训练步数。
2. **评估驱动开发**。GAN 的 loss 不能说明效果，我们养成了
   “每个 checkpoint 都出图对比”的习惯，最终的选择（epoch 180、
   checkpoint-200）都是评估选出来的，不是训练完的最后一个。
3. **工程与算法各占一半**。下载器、显存优化、队列并发、HTTPS 证书、
   文件锁 bug……真正让项目“能用”的时间大头花在工程细节上。
4. **受资源约束的取舍艺术**。8 GB 显存下，我们放弃了“更大的模型”，
   选择了 fp16 + 少步蒸馏 + 双产品线的组合方案，反而覆盖了更多使用场景。
